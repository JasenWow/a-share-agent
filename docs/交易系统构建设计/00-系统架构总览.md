# A股量化分析 Agent 系统 — 系统架构总览

> 本文档定义一个面向 A 股市场的量化分析 Agent 系统的完整架构。
> 系统参考 [anthropics/financial-services](https://github.com/anthropics/financial-services) 的三层架构（Skills / Agents / Connectors），针对 A 股特殊规则和中文数据生态进行本土化适配。

---

## 1. 系统定位与目标

### 1.1 系统定位

本系统是一个 **AI 辅助的 A 股量化研究与投资决策支持平台**，定位为：

- **研究工具**：帮助量化研究员完成因子挖掘、策略回测、组合优化等全流程研究工作
- **决策辅助**：为投资经理提供个股深度分析、市场监控、风险预警等决策支持
- **知识管理**：将 A 股市场知识、量化方法论、监管规则体系化为可复用的 Skill

### 1.2 核心目标

| 目标 | 描述 |
|------|------|
| T+1 感知 | 全系统从信号生成到回测标签构建均内嵌 T+1 结算约束 |
| 合规优先 | 内建涨跌停限制、申报频率上限（15笔/秒）、印花税等 A 股规则 |
| 可追溯性 | 每个分析结论必须附带数据来源、计算过程和引用链路 |
| 人机协作 | 所有交易决策必须由人类确认，系统不执行任何自动下单 |

### 1.3 系统边界（不做什么）

| 不做 | 原因 |
|------|------|
| 自动下单/程序化交易 | 监管合规要求，且需 broker 柜台接口（非本系统范围） |
| 高频交易策略 | A 股 15 笔/秒的申报限制使 HFT 空间极小 |
| 基本面财务建模 | 已有 financial-services 的 comps/DCF 等技能覆盖 |
| 替代人类判断 | 系统输出均为分析建议，最终决策权在人 |

## 3. Agent 清单

### 3.1 Agent 总览表

| Agent | 代号 | 核心职责 | 触发方式 | 子Agent委派 |
|-------|------|---------|---------|------------|
| **选股筛选 Agent** | `screener` | 基于多因子模型的股票初筛与排序 | `/screen` | 可委派 FactorAnal |
| **个股研究 Agent** | `researcher` | 单只股票的深度基本面与技术面分析 | `/research` | 可委派 Screener |
| **因子分析 Agent** | `factor-analyst` | 因子挖掘、检验、组合与有效性监控 | `/factor` | 无 |
| **回测评估 Agent** | `backtester` | 策略历史回测、绩效归因、过拟合检测 | `/backtest` | 可委派 FactorAnal |
| **组合管理 Agent** | `portfolio` | 组合构建、优化、风控与调仓建议 | `/portfolio` | 可委派 Screener, Backtester |
| **市场监控 Agent** | `monitor` | 实时行情监控、异动预警、市场情绪跟踪 | `/monitor` | 无 |

### 3.2 Agent 详细说明

#### 3.2.1 选股筛选 Agent (Screener)

```
触发: /screen 或 "帮我筛选xxx条件的股票"
输入: 筛选条件（行业、市值、因子暴露等）
输出: 排序后的候选股票列表 + 筛选逻辑说明
```

**工作流**:
1. 解析用户的筛选条件
2. 调用 Connector 获取最新市场数据
3. 应用申万一级行业分类过滤
4. 执行多因子打分（小市值、反转、高股息、低波动等 A 股强因子）
5. 应用 A 股约束过滤（ST 排除、涨跌停状态、停牌、上市天数不足）
6. 输出排序结果，附因子暴露和排名变动

**A 股特殊处理**:
- ST/\*ST 股票默认排除，需用户显式确认
- 涨跌停板上的股票标记为不可交易
- 新股上市不满 60 个交易日默认排除（IPO 效应期）

#### 3.2.2 个股研究 Agent (Researcher)

```
触发: /research 或 "分析一下xxxx"
输入: 股票代码或名称
输出: 深度研究报告（Markdown）
```

**工作流**:
1. 获取个股基本信息、财务数据、行情数据
2. 申万行业归属与同业对比
3. 北向资金持仓变化分析
4. 龙虎榜数据解读（如有）
5. 技术指标分析（均线、MACD、RSI、布林带等）
6. 分析师覆盖情况与评级汇总
7. 综合评估与风险提示

#### 3.2.3 因子分析 Agent (Factor Analyst)

```
触发: /factor 或 "测试xxx因子的有效性"
输入: 因子定义、测试参数
输出: 因子检验报告（IC/IR/分层回测/换手率分析）
```

**工作流**:
1. 因子定义与计算逻辑确认
2. 因子预处理流水线：
   ```
   原始数据 → MAD去极值 → ZScore标准化 → 申万行业+市值中性化
   ```
3. IC 分析（Rank IC、Normal IC）
4. 分层回测（五分位/十分位）
5. 因子衰减分析
6. 换手率与交易成本估算（含印花税 0.05%）
7. 因子相关性矩阵
8. 输出检验报告，附有效性判断标准

#### 3.2.4 回测评估 Agent (Backtester)

```
触发: /backtest 或 "回测xxx策略"
输入: 策略逻辑、回测参数
输出: 回测报告（收益率曲线、绩效指标、归因分析）
```

**A 股回测内建约束**:
- T+1 交易：当日买入次日才能卖出
- 涨跌停不可成交：涨停无法买入，跌停无法卖出
- 印花税 0.05%（卖出方）
- 佣金默认 0.025%（双边）
- 申报频率限制（15 笔/秒，回测中不触发但需提示）
- 标签构建：信号 T 日 → 交易 T+1 开盘 → 实现 T+2 收益

**工作流**:
1. 解析策略逻辑，生成信号时间序列
2. 应用 T+1 约束生成交易信号
3. 模拟撮合（考虑涨跌停和成交量限制）
4. 计算资金曲线和持仓历史
5. 绩效指标计算（年化收益、夏普、最大回撤、Calmar 等）
6. 过拟合检测（样本外测试、参数敏感性分析）
7. 输出完整回测报告

#### 3.2.5 组合管理 Agent (Portfolio Manager)

```
触发: /portfolio 或 "优化我的组合"
输入: 当前持仓、目标约束、优化目标
输出: 调仓建议 + 风险报告
```

**工作流**:
1. 获取当前持仓和最新市场数据
2. 风险暴露分析（行业集中度、风格因子暴露）
3. 组合优化（均值-方差 / 风险平价 / Black-Litterman）
4. A 股约束注入：
   - 单票权重上限（默认 10%）
   - 申万一级行业偏离限制
   - 涨跌停状态下的可操作性检查
5. 生成调仓建议（考虑交易成本和冲击成本）
6. 风险预警（VaR、波动率、相关性突变）

#### 3.2.6 市场监控 Agent (Market Monitor)

```
触发: /monitor 或 "今天市场有什么异动"
输入: 监控条件（可选）
输出: 市场异动报告、资金流向、情绪指标
```

**监控维度**:
- 大盘指数与板块轮动（申万一级行业涨跌幅排名）
- 北向资金实时流向（沪股通/深股通）
- 龙虎榜异动数据
- 涨跌停统计（涨停家数、跌停家数、封板率）
- 市场宽度指标（上涨家数/下跌家数、创新高/新低）
- 融资融券余额变化
- 特殊事件预警（停复牌、大宗交易、股东增减持公告）

## 5. MCP 连接器清单

### 5.1 连接器总览

所有连接器以 MCP Server 形式提供，统一在 `.mcp.json` 中配置。

#### 开源数据源（免费）

| 连接器 | MCP Server | 提供数据 | 调用频率 | 稳定性 |
|--------|-----------|---------|---------|-------|
| **AKShare** | `mcp-akshare` | 实时行情、历史 K 线、北向资金、龙虎榜、申万分类、融资融券 | 实时~日频 | 中 |
| **BaoStock** | `mcp-baostock` | 历史 K 线（日线/周线/月线/分钟线）、财务数据、除权除息 | 日频 | 高 |
| **通达信** | `mcp-tdx` | 实时行情快照、Level-2 数据（需接口）、板块资金流 | 实时 | 中 |

#### 付费/积分制数据源

| 连接器 | MCP Server | 提供数据 | 调用频率 | 说明 |
|--------|-----------|---------|---------|------|
| **Tushare** | `mcp-tushare` | 全面财务数据、指数成分、基金持仓、期货数据 | 日频 | 需积分，高完整性 |
| **Wind API** | `mcp-wind` | 全市场实时数据、宏观经济、研报数据 | 实时 | 机构标配，需付费 |

#### 本地与辅助数据

| 连接器 | MCP Server | 提供数据 | 调用频率 | 说明 |
|--------|-----------|---------|---------|------|
| **本地 SQLite** | `mcp-sqlite` | 本地因子库、回测结果、策略参数 | 按需 | 缓存加速 |
| **经济日历** | `mcp-calendar` | A 股交易日历、财报披露日、宏观数据发布日 | 日频 | 避免未来信息 |
| **新闻情感** | `mcp-news-sentiment` | 财经新闻采集、情感分析、事件提取 | 实时 | 辅助决策 |

### 5.2 连接器优先级与降级策略

```
数据请求优先级：
  Wind > Tushare > AKShare > BaoStock > 本地缓存

降级策略：
  1. 主数据源超时/失败 → 自动切换备选数据源
  2. 实时数据不可用 → 降级为最近收盘数据
  3. 所有外部源不可用 → 使用本地缓存 + 明确标注数据时效
```

## 7. 安全设计

### 7.1 核心安全原则

```
┌─────────────────────────────────────────────────────┐
│                  安全防护层                            │
│                                                     │
│  ┌─────────────┐  ┌─────────────┐  ┌────────────┐ │
│  │ Human-in-    │  │ No Auto-    │  │ Citation   │ │
│  │ the-Loop    │  │ Trading     │  │ Mandate    │ │
│  │ 人类确认     │  │ 禁止自动交易 │  │ 强制引用    │ │
│  └─────────────┘  └─────────────┘  └────────────┘ │
│                                                     │
│  ┌─────────────┐  ┌─────────────┐  ┌────────────┐ │
│  │ A-Share     │  │ Data        │  │ Output     │ │
│  │ Constraints │  │ Freshness   │  │ Scope      │ │
│  │ A股约束     │  │ 数据时效检查 │  │ 输出边界   │ │
│  └─────────────┘  └─────────────┘  └────────────┘ │
└─────────────────────────────────────────────────────┘
```

### 7.2 安全护栏详细说明

#### 7.2.1 人类确认 (Human-in-the-Loop)

| 检查点 | 描述 | 实施方式 |
|--------|------|---------|
| 调仓执行 | 组合管理 Agent 输出调仓建议后，必须由人类确认 | 输出 `⚠️ 待确认` 标记，不自动执行 |
| 策略上线 | 回测通过后，策略参数需人类审核确认 | 输出审核清单，逐项确认 |
| 异常交易 | 监控 Agent 发现异常时，仅预警不操作 | 推送通知 + 原因分析 |

#### 7.2.2 禁止自动交易 (No Auto-Trading)

- 系统架构层面 **不包含** 任何交易执行模块
- 不对接券商柜台接口（CTP、XTP 等）
- 所有输出均为 "分析建议" 或 "待确认指令"，不构成交易指令
- Agent 系统提示词中内建以下规则：
  > "你是一个分析辅助系统。你绝不能生成可直接执行的交易指令。所有输出都是研究建议，需要由具备资质的投资人员进行审核和决策。"

#### 7.2.3 强制引用 (Citation Mandate)

- 所有数据驱动的结论必须标注：
  - 数据来源（如 "数据来源: AKShare，获取时间: 2024-01-15 15:30"）
  - 计算方法（引用对应 Skill 文件）
  - 数据时效（标注是否为实时/收盘/延迟数据）
- Agent 输出末尾必须包含引用区块

#### 7.2.4 A 股特定约束

| 约束 | 检查方式 | 影响范围 |
|------|---------|---------|
| **T+1** | 回测引擎强制执行，信号 T 日生成，T+1 才可执行 | Backtester, Portfolio |
| **涨跌停限制** | 涨停板上不可买入，跌停板上不可卖出 | Screener, Backtester, Portfolio |
| **ST 警告** | ST/\*ST 股票标注风险警告，默认排除 | Screener, Researcher |
| **申报频率** | 不涉及（系统不做自动交易），但在 Skill 中记录 15 笔/秒限制 | 知识记录 |
| **印花税** | 所有成本计算中强制包含卖出方 0.05% 印花税 | Backtester, Portfolio |
| **停牌处理** | 停牌股票标记为不可交易，回测中跳过 | 全部 Agent |
| **行业集中度** | 申万一级行业偏离度超阈值时预警 | Portfolio |

### 7.3 输出边界 (Output Scope)

- 系统输出 **仅限于** 分析报告、数据图表、调仓建议
- 输出 **不得包含**：投资建议（"你应该买/卖"）、收益承诺、风险评级
- 所有报告必须包含标准免责声明：
  > 本报告由 AI 分析系统生成，仅供参考，不构成任何投资建议。投资有风险，入市需谨慎。过往业绩不代表未来表现。

### 8.5 关键差异总结

| 维度 | financial-services | A 股量化系统 | 原因 |
|------|-------------------|-------------|------|
| **目标用户** | 投行分析师、基金经理 | 量化研究员、投资经理 | 业务场景不同 |
| **核心工作流** | 建模、报告、尽调 | 筛选、回测、组合优化 | 工作模式不同 |
| **数据生态** | 全球付费终端 (Bloomberg/FactSet) | A 股免费+付费混合 (AKShare/Tushare) | 市场基础设施不同 |
| **交易规则** | T+0、无涨跌停 (美股) | T+1、涨跌停限制 | 市场规则不同 |
| **因子体系** | 通用因子（动量、价值、质量） | A 股特有因子（小市值、短反转、北向资金） | 学术研究差异 |
| **语言** | 英文 | 中文 | 本土化需求 |
| **行业分类** | GICS | 申万行业分类 | 分类标准不同 |
